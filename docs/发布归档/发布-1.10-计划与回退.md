## 第 3 步：桌面版构建链（顺序不能乱）

**关键事实**：`build-stage-workbuddy.py` 打包的输入是**本机 `D:\Program Files\Rime`**，不是仓库 `rime/`。
所以桌面上 1.10 的正确顺序是：

1. 先把权威文件铺进本机 Rime 目录（仓库 `rime/` → `D:\Program Files\Rime`，含 `lua/`）。
2. 托盘「重新部署」一次，确认方案编译通过、`F4` 有「五笔·拼音」、`vb/hao/pingguo/agjs/good/mqfd` 全对，
   缩写开关能开能关。**这台机器现在还是旧编译产物，wnwb 下架要这次部署才生效。**
3. 跑 `build-stage-workbuddy.py` → 生成 `packaging/stage/{payload,patched}` + `MANIFEST.txt`。
4. 同步到 `packaging/release/config`（安卓脚本 `SRC` 就是读这个目录，两边必须一致）。
5. 版本号 5 处：`packaging/installer-src/install.nsi` 第 6 行 `OutFile`、第 491 行 `DisplayVersion`；
   `.github/workflows/build-installer.yml` 第 20 行 `INPUTS_URL` tag、第 24 行 `EXPECTED_VERSION`；
   `packaging/winget/manifests/.../1.9.10/` 整目录复制成 `1.10/` 并改里面 3 个文件的版本号与 URL。
   （`build-inputs-v1.9.10` 那个 release tag 里的 7z 是引擎二进制，内容不变可以先沿用，
   只要 CI 的 `EXPECTED_VERSION` 与 nsi 对上。）
6. 打 NSIS 安装包 → 本机**覆盖安装**（不卸载）→ 再部署 → 全量回归。
7. 文档版本行：`README.md` 下载块 / 功能一览 / 版本沿革加 v1.10 条目、`功能清单.md` 第 3 行、
   `docs/code-signing.md` 那句「当前发布的 v1.9.10 尚未签名」。

回退：`packaging/stage` 与 `release/config` 是可再生产物，改坏就重跑第 3 步；
`install.nsi` 等文本改动都在 git 工作区，未提交前 `git checkout -- <文件>` 即回。
装到机器上的东西：装之前的旧安装包留在 `packaging/dist/`，重装旧包就能退回去。

## 第 4 步：安卓版必须一起做的两件事（顺序有讲究）

1. **先修 seed 版本化，再重建 seed。** 现在首次启动落地器写的是固定标记 `sansheng_seed_v1.done`，
   老用户覆盖安装 1.10 后一看标记已存在 → **整段跳过**，手机上的 wnwb 和署名头永远不会更新。
   这直接违反「覆盖安装就生效」，是 1.10 的阻塞项，改法：标记名带数据版本
   （`sansheng_seed_v2.done`），落地器按标记逐个比对、只补没落过的版本；老标记保留不动。
   改这个要重编 `classes3.dex`，动 `build-android-qoder.py`。

   `socket`/`mime core.dll`，832 KB，在安卓纯无用且属于未授权转发）与内部调试说明 `_某某版本.txt`。
3. `build-android-qoder.py` 第 28 行 `VERSION = "1.9.10-android"` → `"1.10-android"`，
   versionCode 1911 → 1912；`verify-android-qoder.py` 全项过；重新签名（密钥在工程外

4. 更新发布包、`SHA256SUMS`、两份 `THIRD_PARTY_NOTICES.md` 里安卓那 76 个 / 20,672,965 B 的**预估**数字
