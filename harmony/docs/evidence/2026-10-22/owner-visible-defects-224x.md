# 主人 22:3x 三条「小问题」的实测根因（H-106 / H-107 / H-108）

时间：2026-10-22 22:4x　·　取证人：Qoder　·　设备：Mate 80 `7GL0226408083897`

主人原话：「键盘不能折叠，弄好了但右上角多出一个箭头来，一会儿又不能折叠了，九宫格切换 abc 好几轮都没改好，桌面没图标了告诉他了，还是没找回来，都是小问题，不能一次搞定。」

**结论先说**：前两条不是两个 bug，是**同一种改法**造成的——把「看得见的键」换成「藏起来的长按」。第三条（图标）我这边量下来配置和素材都是好的，缺的是真机那一眼。

## 一、H-106 键盘不能折叠 / 右上角多出一个箭头

**实测对照**（`git show HEAD:` 与工作区同一处，HEAD = `3c94d66`，18:40 那版）：

| 位置 | HEAD（18:40 提交版） | 工作区（21:51） |
|---|---|---|
| 底栏最左「收起键盘」键 | **有**：`BottomBar()` 第一格，`SymbolGlyph(sys.symbol.chevron_down)` + `.layoutWeight(0.7)` + `onClick → keyboardController.hideKeyboard()`（HEAD `:1793-1815`） | **没有**：全文件 `hideKeyboard` 只剩 1 处 |
| 候选栏右端 ▼/▲ 键 | 有（HEAD `:991/995`），短按=展开/收起候选网格，**不管折叠** | 有（`:1002/1006`），短按=展开网格，**长按 500ms = 折叠键盘**（`:1016-1021` `LongPressGesture → hideKeyboard()`） |

**所以主人的观感完全对得上代码**：

1. 「键盘不能折叠」= 底栏那个**看得见的**收起键被删了，屏上再没有任何写着/画着「收起」的东西。
2. 「右上角多出一个箭头」= 折叠被挪到了候选栏最右那个箭头键上（它在键盘**上方**的候选条右端，就是右上角）。这个箭头本来就存在（是展开候选网格的 ▼），现在又多了个折叠职责，于是它从「一个装饰性小箭头」变成「主人眼里新冒出来的东西」。
3. 「一会儿能折叠一会儿不能」= **同一个键两种含义**：短按展开网格、长按 500ms 才折叠，且没有任何可见提示。按得快就是展开，按住不放才是折叠——用户不可能稳定复现。

**修法（一句话，不需要重写）**：底栏恢复一个独立可见的「收起键盘」键（就是 HEAD 那一格，代码现成、位置现成），候选栏箭头键**只保留展开/收起网格**这一个职责。**长按折叠可以留着当快捷，但不能是唯一入口。**

## 二、H-107 九宫格 ↔ 26 键切换好几轮没改好

**实测**：`KeyboardIndex.ets:83-84` 的注释就写着这次改动 —— 「底栏删『九键』键（撤销 D-009）：布局切换改长按 ?123/ABC 弹 LayoutMenu」。现在全文件里布局切换只有一条路：`:2109` 长按 `?123/ABC` → `showLayoutMenu = true` → `LayoutMenu()`（`:2232`，两个选项 26键 / 九键）。

**同一根因**：H-054 时代底栏有**一级可见入口**（26 键显示「九键」、九键显示「26 键」，点一下就切）；D-014 把它删了，换成藏在长按里。主人说「九宫格切换 abc 好几轮都没改好」——因为改的从来不是同一个问题：**他要的是一个看得见的切换键，CodeArts 每轮都在优化一个看不见的菜单。**

**修法**：底栏放一个**常驻且会换字**的布局键（26 键态显示「九键」、九键态显示「26 键」，回到 H-054 的语义），`?123/ABC` 回归本职（字母页 ↔ 符号页）。长按弹菜单可以保留作快捷。

## 三、两条的共同根因（这才是「改一处错一处」的真原因）

底栏宽度是固定的。加一个可见键，空格就要窄一点；CodeArts 每轮都在重排 `layoutWeight`（M-085 那轮：hide 0.8→0.7、?123 1.2→1.0、space 3.5→4.5），**而他把「放不下」解成「把键删掉、改成长按」**。于是：改宽度 → 键被删 → 主人说功能没了 → 再加回来 → 宽度又挤 → 再删…… 这就是转圈。

**终止条件**：把底栏键位**定死成一张表**，谁都不许再用「藏进长按」来解决宽度问题。建议固定 6 格：

`收起键盘` · `布局切换(九键/26键)` · `?123/ABC` · `emoji/符号` · `空格（吃剩余宽度）` · `中英/切换语言`

放不下就减键帽内边距、减字号、减 `KEY_MARGIN`，**不许删功能键**。这条是产品决定，主人点头就是最终版。

## 四、H-108 桌面图标「找不回来」——我这边量到的事实

| 量什么 | 结果 |
|---|---|
| `AppScope/app.json5:7` | `"icon": "$media:layered_image"` ✅ |
| `AppScope/resources/base/media/layered_image.json` | 109 B，`layered-image.background=$media:background` / `foreground=$media:foreground`，自 10-19 未改 ✅ |
| `background.png` | 5,533 B，**合法 PNG，1024×1024，8bit，colortype=2（RGB 不透明）** ✅ |

| 系统侧实际解析（`bm dump -n com.sansheng.ime`） | `"iconPath": "$media:layered_image"` ✅ 包装着、系统认得 |

⇒ **配置、素材、装机记录三层都是好的，问题不在引用断链。** 剩下两种可能，只能靠真机那一眼区分：

- **A：桌面图标显示成空白/默认灰图** ⇒ 分层图标合成失败（华为桌面这层渲染问题），修法是把 `app.json5` 的 `icon` 从 `$media:layered_image` 改成**单层** `$media:app_icon` 并放一张成品 PNG（这条路我在 M-088 就列过，是图标问题的兜底路线，改一个字段）。
- **B：应用整个从桌面消失（但还在应用列表里）** ⇒ 与图标无关，是 launcher 里被移出/快捷方式没了，重装即可。

**我不猜，也不让他猜**：手机解锁后我用 `snapshot_display` 拍桌面，一眼定 A/B，再派单。**这也是我这几轮做得不够的地方——H-097 我从头到尾只验了「包内两层与素材逐字节相同」，从没验过「桌面上看得见图标」，判据本身就缺一格。** 现在把它写进闸门。
