# 性能基线（M5 ④）

> 设备：Mate 80（`7GL0226408083897`），竖屏 1280×2832，HarmonyOS NEXT 真机。
> 被测包：H-066 验收包（M-049 触摸体系 + D-012 `script_translator@pinyin`，**未含** H-067/H-068；`DATA_VERSION=m5-pinyin-v18`）。
> 方法：`hdc shell` + `uitest uiInput` 注入，hilog 时间戳取值，`/proc/<pid>/status` 与 `hidumper --mem` 取内存。每项重复 2–3 次，取范围。
> 注：本文件是 **M-050 之前** 的前置基线；M-050 视觉批次后按同一方法复测，最终数字以复测为准。

## 1. 冷启（IME 进程被杀后首次弹键盘）

| 指标 | 定义 | 实测（3 次） | 均值 |
|---|---|---|---|
| 面板可见 | 点击输入框 → `SSKeyboardController panel created` | 667 / 671 / 867 ms | **735 ms** |
| 引擎就绪 | 点击输入框 → `SSRealRimeEngine ready` / `engine ready` | 2,013 / 2,027 / 2,179 ms | **2,073 ms** |
| 首帧可用 | 面板可见 → 引擎就绪（期间按键行为） | 约 1.34 s | **1.3 s** |

- 引擎加载（Rime + 词库）是冷启的主要成本，约占 2.07 s 中的 1.3 s；`SSRimeData data m5-pinyin-v18 already present` 说明数据已解压，不是重复部署。
- **缺陷（H-068）**：面板 0.7 s 已可见，但 1.3 s 内按下的键被静默丢弃。实测在 `panel created` 后 0.74 s 点 `n`，截图为空候选、无预编辑（`docs/evidence/2026-10-22/m5-68-cold-start-lost-key.png`），日志只有 `state: cand=0 all=0`。
- **已修**：ready 前按键入队、ready 后按序回放（D-013），待与 M-050 同批构建验证；修复只消除吞键，不减少 2.07 s 加载时间。

## 2. 按键到候选（热态）

`nihao` 连打 5 键，取 `InputKeyFlow ac: down` 到对应 `SSKeyboardIndex state` 的时间差：

| 样本 | Down → state |
|---|---|
| 第 3 键 | 123 ms |
| 第 4 键 | 120 ms |
| 第 5 键 | 115 ms |

- 区间 **115–123 ms/键**（含 Rime 查询、`notify`、ArkUI 重绘）。5 键串打无丢键。
- 这部分是纯热路径，M-050 视觉改造不得把它推高；复测同样取 `ni`/`ji` 即可。

## 3. 候选翻页 / 展开网格

- 候选栏左右 `drag` 后 `InputKeyFlow` 记 `SWIPE RACC, T: Column`，页面由第 1 页 `你好 hello 你 拟 尼` 切到第 2 页 `呢 泥 妳 昵 腻`（`perf-kb.png`），反向 `drag` 回第 1 页。
- 翻页是 UI 切片内状态更新（H-060 记账），不发引擎页请求、无 `state` 日志；**该包没有帧级埋点，无法给出帧耗时**。截图法上界：手势结束到截图完成 638 ms（含 `screenScan` 自身开销），期间页面已完成切换（`flip-lat.png`）。
- 展开网格沿用 H-059 本页内 6 格翻屏；本包未做帧率量测。
- **待办**：M-050 合并后请 CodeArts 在翻页/网格切换处各加 1 行时间戳日志（不改行为），复测「手势结束 → 新页首帧」毫秒数；若 >100 ms 再优化。

## 4. 常驻内存

| 状态 | VmRSS | PSS（hidumper） | VmHWM |
|---|---|---|---|
| 冷启后空闲（键盘可见、无输入） | 155,812 kB ≈ **152 MiB** | 101,614 kB ≈ **99 MiB** | 162,124 kB ≈ 158 MiB |
| 输入 `nihao` 并翻页/清空后 | 154,032 kB ≈ **150 MiB** | — | — |
| 一次重交互（网格/多页翻动）后 | 212,232 kB ≈ **207 MiB** | 108,448 kB ≈ 106 MiB | 218,952 kB ≈ 214 MiB |

- 常态 150–155 MiB，峰值约 207 MiB；单次重交互后回到 150 MiB，**暂无持续增长证据**，不判定泄漏。
- 与 Android 三生（未量化）暂不可比；M6 上架前若需压到 100 MiB 以内，优先查 Rime 词库映射与 JS 候选缓存，不在 M5 动。

## 5. 结论与下一步

1. 四项里最慢、且用户可感知的是 **冷启 2.07 s**；H-068 已把「看得见打不进」修掉，加载时间本身留 M6 前评估（可选：延迟加载 `pinyin_simp`、减少启动时 translator 数）。
2. 热态 115–123 ms/键为当前基线；M-050 后复测，若 >150 ms 视为回归。
3. 翻页/网格缺帧级数据，M-050 后补埋点再定量；在此之前以截图上界记录，不写「不掉帧」。
4. 内存以 150–155 MiB 常态为准；207 MiB 样本记峰值，不做泄漏结论。

> 方法与 §1–§4 相同：Mate 80（`7GL0226408083897`），`hdc shell` + `uitest uiInput` 注入，hilog/`date +%H:%M:%S.%3N` 取时间，`/proc/<pid>/status` + `hidumper --mem` 取内存。

### 6.1 冷启（3 次）

冷启流程：`aa force-stop com.sansheng.ime` → `aa start … --ps m2_probe 1` → `ime -s com.sansheng.ime` → `uitest uiInput click 600 600` 点输入框。

| 指标 | 第 1 次 | 第 2 次 | 第 3 次 | 均值 | 前置基线 §1 |
|---|---|---|---|---|---|
| 点击 → 面板可见 | 375 ms | 386 ms | 350 ms | **370 ms** | 735 ms |
| 点击 → 引擎就绪 | 1,477 ms | 1,383 ms | 1,378 ms | **1,413 ms** | 2,073 ms |
| onCreate → 引擎就绪 | 1,548 ms | 1,447 ms | 1,438 ms | **1,478 ms** | — |

- 引擎分解：librime 1.16.1 加载 ≈**779 ms**、`prebuild` 63–68 ms、`deploy` 65–66 ms、schema 部署 ≈285–419 ms；其余为 JS/ArkTS 初始化与回调调度。
- 比前置基线快约 0.66 s（面板）/0.66 s（引擎）。本轮 3 次样本稳定，但**不能归因为代码优化**：数据早已解压（`already present`），差异更可能来自系统文件缓存/后台负载；记为「同机当前基线」，首次开机后首启可能回到 2 s 量级。
- 未达标项仍是引擎加载：面板 0.37 s 可见后到 1.41 s ready 之间约 **1.04 s** 只能靠 H-068 输入队列兜底——用户能打、但候选要等 ready 才出。加载时间本身 M5 不动，留 M6 前评估（延迟加载 `pinyin_simp`、减少启动 translator）。

### 6.2 按键到候选（热态）

`nihao` / `ji` / `j` / `i` 逐键注入，取 `InputKeyFlow ac: down` → 对应 `SSKeyboardIndex state`：

| 样本 | Down → state |
|---|---|
| `ni` 的 n / i | 126 / 118 ms |
| `ji` 的 j / i | 126 / 79 ms |
| 单键 j / i（二轮） | 147 / 126 ms |

- 区间 **79–147 ms，中位 126 ms**；前置基线 115–123 ms。
- 判定：**未越过 §5 的 150 ms 回归线**，但高位 147 ms 比基线高约 24 ms。样本小、含一次首键冷路径，记为同量级、不判定回归；M-050 视觉改造没有把热路径推高一个档位。

### 6.3 翻页 / 展开网格

- 候选栏横滑（y≈1985，300 ms）从第 1 页切到第 2 页：`ji` 全池 **all=50、5 条/页**，第 2 页 `几机既急集`（`perf-flip/2/3.jpeg`）；滑动后 **≤0.5 s 的截图**已显示新页，hilog 无引擎页请求，确认是 UI 切片内切换。
- 展开网格（`perf-grid.jpeg`）：第 1 屏只渲染本页 5 条，**3+2 排列、右侧约 280 px 空白**——这是 H-065④「每行少 1 格」的直接视觉证据；M-050-re2 改 Grid + `1fr` + 4 vp gap 后复测：竖屏 4 格/行、横屏 6 格/行全渲染、右侧无空白，竖屏本页 5 条页码 1/1、横屏 `j` 页 1/2→2/2，第 2 屏点选正确（`m5-50r2-02/07/08/09`）。
- **仍无帧级埋点**：只能给出「手势结束 → 截图可见新页 ≤0.5 s」的上界，包含 `snapshot_display` 自身开销；**不写「不掉帧」**。若要定量帧耗时，需在翻页/网格处各加 1 行时间戳日志（M6 可选）。

### 6.4 常驻内存

| 状态 | VmRSS | PSS | VmHWM |
|---|---|---|---|
| 输入中（键盘可见、有预编辑） | 155,844 kB ≈ **152 MiB** | 85,710 kB ≈ **84 MiB** | 161,680 kB ≈ **158 MiB** |
| 翻页 + 展开网格后 | 163,924 kB ≈ **160 MiB** | 87,688 kB ≈ **86 MiB** | 163,940 kB ≈ **160 MiB** |

- 与 §4 前置基线（常态 150–155 MiB、峰值 207 MiB）相比：常态一致，**207 MiB 峰值本轮未复现**，重交互后仅 +8 MiB 且 HWM 未抬升。
- 判定：**无持续增长证据**，不判定泄漏；M5 不压内存，M6 上架前如需 <100 MiB 再查词库映射与候选缓存。

### 6.5 H-068 冷启连打

面板可见、引擎未 ready 的窗口内连打 3 个字母：ready 后按序回放，预编辑与候选一次出齐，**无丢键**（M-050-review）。对照修复前样本 `m5-68-cold-start-lost-key.png`（候选空、无预编辑）。该修复不缩短 1.41 s 加载，只保证「看得见就能打、打了不丢」。

### 6.6 小结

1. 最慢项仍是**冷启引擎 1.41 s**（本轮同机热缓存条件）；面板 0.37 s + H-068 队列把「丢键」问题消除，但候选仍需等 ready。M6 前评估冷启优化，不在 M5 动。
2. 热态 79–147 ms/键（中位 126 ms），未越 150 ms 回归线。
3. 翻页/网格无帧级数据，re2 装机后补 3+2 → 4+4（竖屏）/ 6+6（横屏）的视觉验收；不写帧率结论。
4. 内存 152→160 MiB，无增长证据。
