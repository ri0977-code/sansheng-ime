**四条实测结论（逐条对上主人的抱怨）**
1. 面板**总高度与字母键盘相同**（3 行键 + 底栏），不额外吃屏幕 → 不会出现「下面的符号都看不到」。
2. 分类是**顶部一排 8 个图标**（🕐最近 / `1?#` / `( )` / ⇥箭头 / ±÷数学 / ①序号 / ◇几何 / [全]全角），**一屏放得下、不需要左滑** → 对上「左滑半天滑不完」。
3. 内容区是 **3 行 × 10 列 = 30 格一屏全可见**（点 `①` 立刻变 ①②③…⑩ / (1)…(10) / ❶…❽+⌫，见 `a5`），第 1 行数字**常驻不换** → 数字和符号同屏，不用来回切。
4. 键是 **1080/10 ≈ 108 px 宽**（约 36 vp）的**扁平米字格、无间距**，字形大但键不肥 → 对上「键又特别大」。

### 1.3 与主人描述的差异（如实记录）

主人描述的是「上面九格 1-9，下面空格/0/返回，两个侧边栏放退格回车」——那是**搜狗/小艺的九宫格数字盘**形态；**自家安卓版实际是 3×10 平铺 + 顶部图标分类条**。两者都满足「一屏看全、不左滑、键不超大」，且**换排布只是网格参数**。本规格先按**自家安卓实测结构**实现（主人指定的参考对象），若要改成 12 宫格 + 双侧栏，只需把主区从 3×10 换成 3×4 并把功能键移到侧栏，其余（分类条、常驻数字、扁平键）不变。

## 2. 鸿蒙版现状实测（全部量出来的）

### 2.1 候选行（H-077）

| 项 | 实测值 | 出处 |
|---|---|---|
| 竖屏面板宽 | 360 vp | `KeyboardIndex.ets:66` |
| `availW` | 360 − 40(▼) − 2×8 = **304 vp** | `recomputePageSize()` |
| compact 判据 | `availW > 360` → 竖屏**恒 false** | 同上 |
| 竖屏字号/内距/间距 | 22 fp / 10 vp / 6 vp | 同上 |
| 引擎页大小 | `setPageSize=3 (UI pinned)` | hilog |
| 状态 | `cand=3 all=50 base=0 page=0 next=true uiSize=3 rendered=3` | hilog `tmp-hilog.txt` |
| 屏上观感 | 候选只到行宽 ~55%，右半空白 | `owner-01-portrait-now.png` |

根因四条：① `estimateCandWidth()` 末尾 `return w + 2 * padH;` 每条**多算 20 vp**，而渲染端 `Text` **无 padding**（估算与渲染不同源）；② 按全文估宽，但格子实际被 `Ellipsis` 截断，`river`/`surname` 一条吃掉 1/3 行宽；③ 竖屏落不进 compact 档（22 fp 过大）；④ 展开网格 `gridPageSize()=4×2=8` 格，但内容取自 `pagedCandidates()`（上限 = 行 `uiPageSize`=3）⇒ **8 格最多 3 条**、页码恒「1/1」。横屏正常是因为 compact 生效（18 fp）。

### 2.2 `?123` / 符号面板（H-078）

| 项 | 鸿蒙现状 | 安卓基准 |
|---|---|---|
| 分类导航 | **顶部横向 Scroll 的 116 个文字标签**（13 fp，左右内距 10 vp） | 顶部**固定 8 个图标**，不滑 |
| 数字 | `DIGIT_ROW` 1-9+0 **独占一整行**，且只在符号页 | 第 1 行常驻，与符号同屏 |
| 内容区 | 面板高 − 数字行 − 标签行 − 底栏 ⇒ **只剩 2~3 排** | **3 行 × 10 列 = 30 格全可见** |
| 符号键宽 | `SYMBOL_KEY_W = 48 vp`（宽字符 96 vp）+ `KEY_MARGIN_SM` 4 vp ⇒ 每排仅 6~7 个 | ≈36 vp，无间距，每排 10 个 |

| 底栏 | 多一颗常驻「九键」键（D-009 遗留） | **无九键键**，布局切换走 🌐/长按 |
| 字母键次级字符 | 无 | 数字 + `@ * + - = / # ( )` 等全部可上滑 |

## 3. 目标规格

### 3.1 H-077 · 候选行与展开网格（竖屏密度）

1. **估宽与渲染同源**（推荐）：`estimateCandWidth()` 去掉 `2*padH`，只返回文字宽；`space` 单独计。
2. **单条封顶**：计入宽度取 `min(文字宽, availW*0.30)`（竖屏 ≈91 vp）⇒ 长英文词不再吞行；格子上屏仍走现有 Ellipsis。
3. **字号分档替换 `availW > 360`**：`availW>=620` → 18/6/4；`>=460` → 20/6/4；其余（竖屏 304）→ **18/4/4**。
4. **网格解耦**：`expanded` 时按 `gridCols()*2` 向引擎要页（`setPageSize`），收起时恢复行页大小；H-060 绝对下标记账与 `uiPageStart` 语义不变。
5. **验收（Mate 80 竖屏 + hilog）**：`nihao` 行内 **≥6 条**（含长英文词 ≥5 条），行尾空白 ≤15%；▼ 展开 **8/8 格全满**、页码出现 `2/N`；横屏不回归（≥9 条）；H-058/059/060、A1–A9、点词上屏零回归。

### 3.2 H-078 · `?123` 面板照安卓版重做（P1）

1. **面板高度 = 字母键盘高度**（3 行 + 底栏），删掉「数字行 + 标签行 + 滚动内容区」的堆叠结构。
2. **主区 3 行 × 10 列**：第 1 行常驻 `1-9 0`；第 2、3 行随分类换；**第 3 行末位固定 ⌫**；键宽 = (面板宽 − 左右内距)/10，**键间 margin 归零**，字号 20~22 fp。
3. **顶部分类条 = 一行图标，不横向滚动**：从现有 116 组里收敛成 **8 个一级分类**（最近 / 常用标点 / 括号 / 箭头序号 / 数学 / 序号 / 几何 / 全…），点击即换第 2、3 行内容；**「更多」入口**再进完整分类列表（纵向列，不是横滑）。
4. **底栏与字母键盘同构**：`ABC` ｜ `,` ｜ 空格 ｜ `.` ｜ ⏎，**删常驻「九键」键**。
5. **布局切换入口改为长按 `?123`/`ABC`** 弹「26键 / 九键」（复用 `LangMenu` 浮层形态，切换前 `keyboardController.clear()`）——与华为官方「长按 中/英 键切 26/9 键」同法。
6. **字母键次级字符（同单内做，P1）**：26 键第 1 行字母键左上标 `1-0`，第 2/3 行标 `@ * + - = / # ( )` 等，**上滑直接上屏**（PanGesture 上滑阈值 ≥20 vp）——这是安卓/小艺共同的「不打断拼音拿数字」路径。
7. **数据不动**：`rawfile/symbols/symbols.json`（116 组 / 2093 项）**格式与内容都不改**，一级分类只是 UI 侧的映射表；fallback 表继续兜底。
8. **验收**：竖屏一屏内同时看得见 **数字 10 键 + 20 个符号 + 退格 + 底栏**；任选 3 个分类切换，主区直接换、**全程无横向滑动**；26 键上滑 `q` 出 `1`、上滑 `a` 出 `@`；底栏不再出现「九键」字面键，长按 `?123` 能切 26/9；A1–A9、H-058/059/060/062/063 不回归。
