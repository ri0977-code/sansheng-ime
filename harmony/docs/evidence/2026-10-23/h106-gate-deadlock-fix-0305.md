## 二、改了什么（三个补丁，都在 `scripts/h106_precheck.py`）

最终「本轮待验收交付」的五条判据（全部为必要）：

1. 行**署名**（WIP 第 4 列「负责人」／MAILBOX 第 3 列「发件人」）以 `CodeArts` 开头；
2. 行内含**真实 unsigned 字节数**：≥6 位数字，剔除示例占位 `1234567`，并剔除出现在我自己指令行里的任何数字；
3. **不要求位于台账末尾**（修死锁）；
4. 该字节数**没有被它之后的任何一行回抄过** —— 这条同时是「同一个 HAP 不重复构建」的守卫，代价是**我写验收行时必须把他报的字节数抄进去**（已写进值守提示与 M-115）；
5. 该行**可解析出的时间戳**必须落在「本台账最新可解析时间戳」往前 **3 小时**以内；解析不出时间戳 ⇒ 不算本轮（修复活）。

时间戳正则：`(\d{4})-(\d{2})-(\d{2})[^0-9]{1,4}(\d{2}):(\d)` —— 要求 `2026-10-23 03:10` 这种形式；`~22:35`、`昨天下午`、缺时间戳一律解析失败 ⇒ 不认为属于本轮（第 4 条 M-044-re 的教训）。

代码核心（`delivery_rows()`，取代旧的「只看末行」）：

```python
out = []
for path, pat in ((WIP, r"^\| W-\d+"), (MAILBOX, r"^\| M-\d+")):
    lines = [ln for ln in read(path).splitlines() if re.match(pat, ln)]
    newest = max([ts for ts in (row_ts(ln) for ln in lines) if ts], default=None)
    for idx in range(len(lines) - 1, -1, -1):
        ln = lines[idx]
        if not cell(ln, 2).startswith("CodeArts"): continue
        counts = real_byte_counts(ln)
        if not counts: continue
        after = "\n".join(lines[idx + 1:])
        if any(c in after for c in counts): continue
        ts = row_ts(ln)
        if ts is None or newest is None or newest - ts > FRESH_HOURS * 3600: continue
        out.append((os.path.basename(path), cell(ln, 0), ln)); break
return out
```

（`W-078` 那种同名多行、`M-085-re2` 那种我的回复行，都在「署名」与「未被回抄」两条上被排除；`M-044-re` 在「时间戳可解析」上被排除。）

3 小时这个值是**故意保守**的选择：它只要求「本轮活跃」，不试图精确判定「他刚写完」。窗口太短会在台账被别的东西刷过一轮后误伤真交付（又回到死锁），太长就会复活昨天傍晚的行（就是这次实测到的假阳性）。取 3 小时，同时把「解释怎么写才有效」直接写进 FAIL 文案里，让他看得见规则而不是猜。
