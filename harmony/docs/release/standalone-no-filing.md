# 单机应用免 APP 备案 —— 判定与依据（推翻我之前的说法）

> 撰写：Qoder · 2026-10-22 13:57 · 对应 `docs/RELEASE-READINESS.md` §三.2 与 §七的更正
> **结论：我们这款按「单机应用」申报，无需工信部 APP 备案，只需在 HarmonyOS 开发者中心勾选备案信息。这砍掉了原关键路径里 1~20 个工作日 + 人脸核验那一段。**

## 一、我之前错在哪

`docs/RELEASE-READINESS.md` 2026-10-21 版 §三.2 写的是：「只要发布地区含中国大陆，**必须先完成 APP 备案**（华为官方问答明确：单机应用同样要备）」，并把备案排成上架硬门槛之一。

那句话的来源是**华为开发者问答里的一条 AI 生成回答**（topic 0203225539738472361，2026-09-23），原文「所有上架分发的 App 都需要完成 App 备案，这与应用是否使用服务器无关」。**我拿论坛回答当了官方规则**，没去核《应用审核 Checklist》正文 —— 这是我的流程错误，和「sign 备份已闭合」那次是同一类毛病：结论先说、证据后补。

## 二、官方 Checklist 怎么写的（2026-10-22 13:52 实时抓取正文）

来源：[应用审核 Checklist](https://developer.huawei.com/consumer/cn/doc/App/50170/)（该页为 JS 渲染，已用浏览器取正文，非缓存摘要）

「APP备案」检查项原文：

> 1、请您及时完成APP备案，确保APP备案时填写的主体信息、应用名称、应用包名与在架应用信息保持一致，并保证APP备案号的有效性；
> 2、鸿蒙版APP备案：需在接入商备案系统填写材料时选择"鸿蒙"平台，并添加鸿蒙包名等信息。…
> **3、无需备案类型：单机应用、境外应用。单机应用定义：未通过连接公共互联网提供互联网信息服务的移动应用程序。**境外应用定义：…

「提审 · 备案信息」检查项原文：

> （3）**如果您的应用为单机或您的应用服务器不在中国大陆，请您在 HarmonyOS 开发者中心正确勾选备案信息。**
> 单机应用定义：未通过连接公共互联网提供互联网信息服务的移动应用程序。

两处相互印证，且是同一份官方文档。**判定动作从「办备案」变成「在开发者中心勾选单机」。**

## 三、我们凭什么是单机应用 —— 本机实测证据

| 检查项 | 实测结果（2026-10-22 13:52，仓库当前工作树） | 怎么验的 |
|---|---|---|
| 权限声明 | `entry/src/main/module.json5` 的 `requestPermissions` **只有 `ohos.permission.VIBRATE` 一条** | 正则抽取全部 `ohos.permission.*`，输出为单元素列表 |
| 网络权限 | 全仓 `*.json5` / `*.json` 中 **搜不到** `ohos.permission.INTERNET` 与 `GET_NETWORK_INFO` | 全仓 grep（排除 node_modules 与 build） |
| 网络 API 调用 | ArkTS/C++ 源码里 **无** `createHttp` / `http.request` / `TCPSocket` / `UDPSocket` / `fetch(` / `new URL(` | 全源码 grep，唯一命中是 `RimeDataInstaller.ets` 第 145 行**注释**里提到上游 `socket.lua` 需要 luaSocket DLL（正是我们**没有**移植它的原因） |
| 数据流 | 词库与用户词典全在设备本地（rawfile + 沙箱），无云端接口 | M3/M4 移植链路，`docs/evidence/2026-10-22/apk-data-parity.md` |

**所以「未通过连接公共互联网提供互联网信息服务」这条定义，我们逐条对得上。**

## 四、这个判定的代价与风险（不粉饰）

1. **它把一条硬约束压到了开发侧：以后任何时候都不能加网络权限。** 一旦将来要做「云词库 / 检查更新 / 反馈上报 / 主题下载」，单机身份立刻失效，那时必须补办工信部备案（1~20 工作日 + 人脸），且**已上架版本的申报口径与实际行为不一致，属于 Checklist 里「提供虚假备案信息」那一类风险**。这条要同步给 CodeArts，见 `docs/MAILBOX.md` M-068。
2. **审核员口径可能与文档不同。** 输入法是敏感类目，存在「虽然我们不联网，但仍被要求出备案号」的驳回可能。**成本对比很轻**：先按单机勾选提审 → 若被打回，再启动备案（备案入口和材料我这边已经能填），代价是 1~3 周；而不是现在无条件先花 1~3 周去备一个可能根本不需要案。
3. **激励计划条款里有一句要盯住**：细则第 7 条把「提供虚假APP备案证明」列为取消激励资格的情形 —— 与第 1 点同源，**申报口径必须和包的真实行为一致**，这是唯一不能打折的地方。

---

## 五、上架关键路径因此重排

原路径（错）：**软著/电子版权 → APP 备案（1~20 工作日 + 人脸）→ 提审**
新路径：**软著/电子版权（唯一长周期项）→ 提审时勾选「单机应用」→ 审核 3~7 工作日**

配合 `docs/release/incentive-2026.md` 的 12 月 31 日窗口：**现在真正卡上架的只剩版权证书一条**（走电子版权约 2 周）。主人只需回答 D-006 选哪条路线，其余我这边推。
