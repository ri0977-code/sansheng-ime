## 1. 为什么要补这一轮

08:1x 那轮我给自己留了两个缺口并写在证据文档 §7：① 只验了 `tgtf` 一条词；② 没有设备侧的**阴性对照**。
今天 09:3x 我先按「换一条全新词」去做，结果连着踩到两个坑，逼出这一轮的严格协议：

1. 第一条候选 `ttyn`（处+行+记）离线一查就知道**槽位是占着的**——`wubi86.dict.yaml:108133` 有 `笔记 ttyn 16700000`，
   设备上该码下还已经挂着一条 `自造词 ☯`（自 th / 造 tf / 词 yn ⇒ ttyn）。
2. 第二条候选 `qqqb` 也一样（`多terrible ☯` 已在位）。
   ⇒ 拿「槽位已被占的码」判「这次有没有造出词」，**判据本身不成立**。上一轮我在 expanded 第 5 位看到的「自造词 ☯」，
   完全可能是装机前就在用户词典里的存量词，不是那次实验造的。这句是对我自己上一轮读图的更正。

所以这一轮改成：**同一条码，上屏前拍一遍基线，上屏后再拍一遍，逐像素比**；并且同时跑主人原话那条 `tgtf` 做对照。

## 2. 离线选词口径（可复核）

三字词合并码按 `wubi86.dict.yaml:44-45` 的 `length_equal: 3 → AaBaCaCb`（第一字首码＋第二字首码＋第三字前两码），

## 3. 协议

```
before(打合并码 → 收起态截图 → 展开 → 逐页截图 → 收起 → ⌫清码，全程不上屏)
commit(逐字：码 → 空格上屏，每步截图；最后读输入框正文)
after (与 before 同一套动作)
diff  (before-pageN vs after-pageN，只数候选列表区 y1860..2560 的不同像素)
restart(aa force-stop 杀 App＋:inputMethod → 重开 → 再打合并码)
```

纪律：before/after 阶段**绝不按空格**——不空格就不进 `commit_history`、不触发 `TableTranslator::Memorize`，基线才不会被自己污染。
翻页是否到底**看面板里的 `x/y` 页码**，不看截图字节是否相同（状态栏时钟会让每帧都不同，脚本里那条 md5 停止条件实测无效，已记在 §6）。
候选列表只有截图里有（H-116：`dumpLayout` 取不到输入法窗口）。

## 4. 结果

### 4.1 `vxxk`（干净槽位）＝造得出、也记得住 ✅

| 阶段 | 输入框正文 | 打 `vxxk` 的候选（展开面板） |
|---|---|---|
| before | 空 | 预编辑串显示 **`vx xk`**（两段）；候选 1/1 页：`姆强 mujian…` / `妣 bi` / `deceased` / `姆 mu` … —— **没有「好红强」** |
| commit | `好红强`（逐字读到 好→好红→好红强） | — |
| after | `好红强` | 预编辑串变成 **`vxxk`**（一段＝整码命中）；候选 1/1 页只剩 **`好红强 haogongjiang ☯`** 排第 1 |
| restart（杀两进程重开，输入框回到占位符「点这里试打一行」） | 空 | **仍是 `好红强 haogongjiang ☯` 第 1 位** |

逐像素（候选区 y1860..2560）：收起态条 **19,651** 个像素不同，展开页 **433,354 / 486,244 / 486,244** 个像素不同 ⇒ 不是读图错觉。
图：`cc-before-00-vxxk.png`、`cc-before-page1.png`、`cc-commit-in-*.png`、`cc-commit-out-*.png`、`cc-after-page1..3.png`、`cc-restart-page1.png`。

三条含义：① 造词链在鸿蒙真机上**通了**（`Memorize` → `UnityTableEncoder` 拿到字全码 → 用户词典落盘）；
② 落盘是**真落盘**（杀进程重开还在）；③ `☯` 是 librime 自己的自动造词标记（不是本仓 lua 画的：`Upper_Filter` 在
`wubi_pinyin.custom.yaml:71` 是注释掉的，`lua/Upper_Filter.lua:24` 与 `pinyinAdding_Filter.lua:35` 只读不写；
`librime.a` 偏移 16788028 的字符串表里 `…max_phrase_length\0/max_homographs\0/extended_charset\0…\0 ☯ \0` 挨在一起）。
这一句是对上一轮「☯ 来自我们 lua」说法的更正。

### 4.2 `tgtf`（主人原话那条）＝**本轮是空测试，不是阴性结果**

before 与 after **候选区不同像素 = 0（10 页全 0）**，两次的第 1 位都是 `行不行 xingbuxing`。
原因不是「造不出」，而是**这个词早就在设备上造好了**：离线已确认「行不行」不在任何五笔词典（`tgtf` 在五笔是「称王称霸」），
所以它出现在 `tgtf` 下只能是用户词典里的存量造词——08:1x 那轮造的，今天杀进程重开还在、还因为被点过一次而稳在第 1 位。
⇒ 这条反过来又是一次**跨会话持久 + 调频**的证据；但作为「这次有没有造出新词」的判据，它**无效**（前后必然相同）。
图：`tgtf-before-page1..12.png`、`tgtf-after-page1..10.png`（页码 1/10→10/10 实测，11/12 是到底后重复帧）。

### 4.3 `ttyn`（上一轮那条）＝槽位被占时新词不露出，机制未定

上一轮打 处/行/记 之后 `ttyn` 下 10 页（真 10 页，页码 1/10…10/10 已核）没出现「处行记」，
而该码下已有 `笔记`（词典，权重 1670 万）＋`自造词 ☯`（造词）。
怀疑方向（**未验证**）：`table_translator.h:47 int max_homographs_ = 1;`（由 `<name_space>/max_homographs` 读，`table_translator.cc:225`；我们 schema 没设），
同一码位只放行一条同形词条 ⇒ 新造的词被同码存量词挡住。
判定性实验（谁做都行，三步）：① 在 `wubi_pinyin.custom.yaml` 加 `translator/max_homographs: 3`；
② 升 `DATA_VERSION` 重铺并重编表；③ 装机后重复上一轮那条序列——逐字上屏 处 / 行(tf) / 记(yn)（合并码正好也是 `ttyn`：
处 t… ＋ 行 tf ＋ 记 yn ⇒ `ttyn`），再看 `ttyn` 的候选里「处行记」是否露出。露出＝就是同形条数限制；仍不露出＝另有原因，回来改这一节。
**产品口径**（要不要「新造词临时置顶」）等主人拍板，我不擅自改。

## 5. 结论（给主人的一句话）

鸿蒙端自造词**修好了**：在 Mate 80 上打 好/红/强 三个字，再打它们的合并码 `vxxk`，当场就出「好红强 ☯」并排第一，
杀掉输入法进程重开还在；你原来报的 `tgtf`「行不行」现在也是第一候选（这个词其实早就造好了，所以这轮前后一模一样）。
唯一还没弄清的：**同一个码位上如果已经挤着别的词（比如 `ttyn` 的「笔记」），新造的词不会露出来**——这条我标了未验证，判据和实验都写在 §4.3。

## 6. 本轮踩的坑（写给下一个接手的人）

* 用「截图字节相同」判翻页到底 **无效**：状态栏时钟/网速每秒都在变。要看面板里的 `x/y` 页码。
  脚本里那条 md5 停止条件保留但别信（`cc-after` 那轮它把同样的 1/1 页当成 3 页）。
* 「槽位有没有被占」必须**离线先查**（`h279_pick_new_word_qoder.py`），否则判据从根上就是错的——我前两轮都错在这。
* 逐字上屏要用**字根码整段＋空格**（`vb`␠），不是逐字母；`tf`␠ 上屏的是「行」，`tgtf`␠ 上屏的是「称王称霸」。
* Windows 侧老坑照旧：Python 一律 `PYTHONIOENCODING=utf-8`（否则 GBK 控制台直接炸）。
