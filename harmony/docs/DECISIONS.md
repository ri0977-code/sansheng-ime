3. **所以候选栏 v2 的 ArkTS 代码骨架仍然用 kanonIME（MIT）**，D-001 不变。

**但它有两样东西对我们真有用，已记进 `OPEN-SOURCE.md`**：

## D-005 · 2026-10-21 19:52 · 许可证选 MIT 还是 Apache-2.0 —— **我建议 Apache-2.0，但真正的坑不是这个，是词库的 CC BY-SA**

你说得对，我上一条只丢了一句「H-007 你拍板」就走了，那是把决定推给你却不给依据。下面把差异、利弊、我的推荐和代价一次说清，你回一个词就行。

**先说结论**：① **代码用 Apache-2.0**；② **词库数据不能并进整体许可**，CC-CEDICT 派生的那几份必须单独按 CC BY-SA 4.0 分发并署名（这是硬义务，不是风格选择）；③ 这两条**都不要求你把源码公开**——MIT 和 Apache-2.0 都允许闭源商用，CC BY-SA 只约束**词库那份数据本身**，不传染到调用它的代码。

**MIT 和 Apache-2.0 的实际差别（对我们有意义的只有三条）**：

| 维度 | MIT | Apache-2.0 |
|---|---|---|
| 文本长度/维护成本 | 3 段话，塞进 `LICENSE` 就完事 | 长文本，且**必须**随包保留 `LICENSE`+`NOTICE`，改过的源文件要注明改动 |
| **专利授权** | **没有**。别人日后可以一边让你用他的代码、一边告你专利侵权 | **有明确专利许可**：贡献者自动授权其相关专利；且带「专利报复」条款（谁拿专利起诉我们，他给我们的许可自动终止） |
| 与我们已引入代码的契合度 | 兼容，但要为 Apache 组件单独写声明 | **最自然**——我们 M1 的键盘壳来自 hMixedKeyboard（**Apache-2.0**），OpenCC/librime/pinyin_simp 也是 Apache-2.0 |

**为什么推荐 Apache-2.0**：输入法是**专利密集**的品类（候选排序、九键预测、云端词频都有人注册专利），我们将来要上架、要被同行看见，一张带专利授权的许可比省几行文本值钱得多；而且我们已经在用 Apache-2.0 的代码，选它等于顺着走。**代价**是我这边多半天机械活：写 `NOTICE`、把第三方许可文本收进包里、给改过的源文件加改动说明。**唯一让我选 MIT 的理由**是「我就想要最短最省事的文本」，那你得接受没有专利授权这一层保护。

**真正必须先处理的是词库（已开单 `ISSUES.md` **H-049**，归我）**。我把打进 HAP 的 10 份词库文件头逐个看了，实测三条：

1. **`LICENSES/` 目录根本不存在**——可 `zh2en_pinyin.dict.yaml` 等文件头写着「许可证全文见 `LICENSES/CC-BY-SA-4.0.txt`」，`en2zh_v2_wp.dict.yaml` 写着「MIT 全文见 `LICENSES/MIT-ECDICT.txt`」。**引用是悬空的**，桌面端作者当时就没落盘。
2. **`cn_pinyin_wp.dict.yaml`（1.4 MB，CC-CEDICT 派生）文件头没有任何署名**，只有「Generated by DSH」；`wubi86.dict.yaml` 头里有作者邮箱但没有许可行。CC BY-SA 的「BY」就是**必须署名**，缺了就是违约。
3. **CC BY-SA 的「SA」是传染到派生数据**：我们这几份表是 CC-CEDICT 转换/筛选/加权生成的，属改编作品 ⇒ **这几份 `.dict.yaml` 本身要按 CC BY-SA 4.0 对外提供**（给下载链接或随包附源数据都行），不能只留二进制。**注意范围**：义务只覆盖词库数据，不覆盖 ArkTS/C++ 代码，所以「闭源上架」这条路仍然成立。

**你只需要回一句**：「按你说的 Apache-2.0 办」／「就要 MIT」／「先别动，等 M4 收口」。H-007 那条挂着的「根 LICENSE=MIT vs HAR 声明=Apache-2.0」，无论选哪个我都会把全仓对齐成一份，并把词库分层写进 `LICENSES/` + 应用「关于」页署名。

## D-006 · 2026-10-21 19:52 · 版权证书：官方软著 vs 电子版权 —— **不是二选一，建议双轨**

上一条我把这两样列成「你定一个」，也没给对比，这是我的疏漏。查底后的对比（华为侧两者在**上架审核层面等效**：AGC「应用版权证书或代理证书」接受《计算机软件著作权登记证书》《APP电子版权证书》《软件著作权认证证书》任一）：

| 维度 | 官方软著（中国版权保护中心） | 电子版权证书（第三方存证） |
|---|---|---|
| 出证方 | 国家版权局登记系统 | 第三方机构（时间戳/区块链存证） |
| **周期** | **约 2~3 个月**（走代理加急可压到几周，但要花钱） | **约 3~15 个工作日** |
| **费用** | **登记本身 0 元**（2017-04 起停收登记费）；只有找代理加急才产生几百~上千 | 一般几百元 |
| 材料 | 身份证 + 源程序前后各 30 页 + 软件说明文档 | 类似（源码样本 + 应用信息），线上化 |
| 华为上架认不认 | 认 | 认 |
| **法律强度** | **最硬**：权属的初步登记证据，维权、跨平台（Android/iOS 上架）、转让、尽调都用它 | 弱一档：证明「某时点存在且归我」，遇到较真的对手方可能被质疑 |
| 复用范围 | 全国通用、长期有效（可按版本再登记） | 基本只为过平台审核，换个应用要再买 |

**我的建议：双轨，不冲突。** 先花几百块办**电子版权证书**（约 2 周），用它把上架这条路先跑通；**同时**免费提交**官方软著登记**（2~3 个月），拿到后作为长期权属凭证——将来 Android 版上架、被人抄了要维权、或者要转让/合作，用的都是这张。若你不想碰第三方机构，那就只走官方软著，**代价是上架时间从「约 1 个月」变成「约 3 个月」**。

## D-010 · 2026-10-21 23:19 · **用户词典 tabledb → userdb（LevelDB）＋桥补 finalize**

**背景（M4 阻塞缺陷，run15/run16 实测）**：同会话自调频是好的——run16 连着提交「hello」，候选位次 1 → 0，说明 rime 的学习逻辑与桥的上屏路径都没问题；坏的是**落盘**：`<user>/user.txt` 永远只有 5 行表头（`#@/tick 0` 等），杀掉 IME 进程重开后，自造词与上调过的频率全丢。

**根因（读 vendored librime 源码，不是猜）**：
- `db_class: tabledb` → `DbComponent<TableDb>` → `dict/table_db.cc` → `TextDb` 是**纯内存** `std::map`，数据只在 `Close()` 里 `if (modified_ && !SaveToFile(...))` 才写文件；`Close()` 只在析构时发生。
- 桌面版 Rime 退出会走 `RimeFinalize` → 析构 → 落盘，所以桌面端没暴露这个问题；鸿蒙这边 IME 进程常驻，桥上原本**没有 finalize 出口**，进程被系统杀掉时就什么都没写。
- `db_class: userdb` → `UserDbComponent<LevelDb>` → LevelDB 每次 `Update` 直接写 WAL，不依赖任何收尾回调，进程被杀也不丢。

**决定**：
1. `wubi_pinyin.schema.yaml` 的 `translator.db_class` 由 `tabledb` 改为 `userdb`（附源码依据注释）。
2. `fanxing_napi.cpp` 新增 `finalizeEngine`（`destroy_session` + `finalize`），`RimeEngine` / `RealRimeEngine` / `MockRimeEngine` 补 `finalize()` —— 引擎有正规关闭出口，CodeArts 可在 IME 销毁/切换时调用（**不接也不影响落盘**，LevelDB 已经每次提交落盘；接上是为了释放文件锁、干净退出）。
3. `RimeDataInstaller` 的 `DATA_VERSION` 随之递增，保证老装机升级后拿到新 schema。

**代价与已知影响（写进 INTERFACE.md）**：
- 用户词典文件从 `<user>/user.txt`（明文「词\t编码\t次数」）变成 `<user>/user.userdb/`（LevelDB 目录：CURRENT / LOG / MANIFEST-* / *.log），**不可再用文本编辑器直接看/改**；
- 桌面版旧 `user.txt` 数据**不做迁移**（格式不同；鸿蒙是新装环境，无历史包袱）；
- LevelDB 比 TextDb 占空间略大（保留日志文件），量级在 MB 以内。

**验证计划**：两轮探针——run1 制造学习事件（同会话调频 + 自造词），杀进程重开 run2 比对位次与词条是否还在；证据落 `docs/evidence/2026-10-21/hilog-m4-v17-*.txt`。判据：run2 的跨会话位次 PASS 且 `user.userdb/` 有非空数据文件。
