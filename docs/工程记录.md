# 工程记录：设计原则与已知边界

从主页 README 拆出来的内部记录。两节内容一字未改，只是搬到了这里——
主页给新用户看，这页给后来改代码的人看。

## 设计原则（踩坑总结）

1. 独立文件，绝不整文件替换 `inputShow_Filter.lua`（dsh 旧方案「修一个坏一个」）。
2. 全程 `pcall` + `cand:get_genuine().comment`，任一候选出错不影响输入，**调频/自造词不受影响**。
3. 只改 `comment`，不改候选顺序与身份。
4. **绝不手动往词典里塞词**——遵循 Rime 自动组词（连续上屏后写入 `user.txt`，反查自动读取）。
5. `user.txt` 的 `enc*` 自动编码条目不是规范五笔码，已过滤，不参与反查。

## 已知边界（诚实标注，非缺陷）

- **二进制 userdb 自造词读不到**：Rime 自动组词写入 `.userdb` 的词为二进制，滤镜加载阶段读不到，故这类自造词不显示反查码（方案层限制，非滤镜问题；调频本身不受影响）。
- **罕见字缺拼音**：如 𧟴（U+277F4，五笔码 `gmbq`）是真实字符，仅因拼音词库未收录而无拼音反查。
- **自造词撞车**：`user.txt` 里 Rime 自动生成的 `enc*` 占位码非规范五笔码，被过滤；其自然码可能已被真实词占用（如 `pxra` = 它找）。
- **英文候选的中文释义取决于词库收录**：「中英对照」滤镜（开关 `encnDic`，默认开）会给英文候选补中文释义，实测 `apple → 【apple】n.苹果`、`he → 【he】pro.他`；其字典 `dic_4w_en.txt` 共 39,814 条，以**单词**为主，所以多词短语（`seed pod`、`to save`）和动态候选（CPU / 系统名一类）查不到，就没有释义。
