## 2. 安卓成熟做法（实测行为，有出处）

国内主流中文输入法把「九键 / 26 键」当成**键盘布局**，切换入口是**键盘上一个可见的模式切换键**，一次点击就换布局，不需要进系统设置，也不需要先翻到符号页：

| 来源 | 行为 | 出处 |
|---|---|---|
| 百度输入法（华为 P60 / HarmonyOS 4.0） | 「**长按键盘左下角的中英文切换键**（通常显示为『中』或『英』）→ 弹出菜单 → 选择『拼音26键』或『拼音9键』」，键盘布局立即切换 | [百度输入法手机版怎么切换9键和26键键盘](https://www.php.cn/faq/1742560.html)、[同文镜像](https://m.mizhijia.net/wz/764939.html) |
| 百度输入法（另一路） | 「点击键盘上的『**四个正方形**』菜单按钮 → 输入方式 → 拼音9键 / 拼音26键」 | 同上 |
| 华为输入法 / 小艺输入法 | 「键盘左下角**地球图标**长按 → 弹出选择框：九宫格9键拼音、26键拼音、全屏手写、笔画输入，点选即切」；另有「键盘上方【拼音】按钮 → 选择『拼音-全键』/『拼音-拇指』」 | [不会用手机打字？教您全套键盘用法](https://www.toutiao.com/a7672216889313231404)、[华为26键怎么设置九宫格数字](https://zhidao.baidu.com/question/1896804977678901708.html) |
| 华为输入法（图文） | 「在**华为输入法面板点击『拼音』按钮** → 选择『26拼音全键』」；「按几下 **123 键旁边的地球形按键**即可切换」 | [好记星平板九键怎么换成26键（引用华为输入法说明）](https://wap.zol.com.cn/ask/x_18261341.html)、[华为手机怎么样切换26键双键输入法](https://wap.zol.com.cn/ask/x_30187586.html) |
| 通用规律 | 切换入口 = **键盘左下角 / 功能行左端的模式键**，一次点击直达 | 三条来源一致 |

**抄哪一条**：我们只有两种布局（26 键 / 九键），不需要弹二级菜单，所以取**最直接的形态**——**底栏功能行左端放一个可见的布局切换键，点一下立刻换布局**。这是安卓上「地球/拼/九键」键的简化版，符合主人的「一次到位」要求。

## 3. 选定方案（实现规格）

### 3.1 底栏结构（改后）

```
26 键模式：  [ 九键 ] [ ?123 ] [ 中/英 ] [      空格      ] [ ⌫ ] [ ⏎ ]
九键模式：  [ 26键 ] [ ?123 ] [ 中/英 ] [      空格      ] [ ⌫ ] [ ⏎ ]
符号页：    [ 26键/九键 ] [ ABC ] [ 中/英 ] [     空格     ] [ ⌫ ] [ ⏎ ]
                 ↑ 新增：布局切换键（键面 = 可切过去的那个布局）
                 ↑ ?123/ABC：只在「字母页 ↔ 符号页」之间切
```

- 新键**插在底栏最左**，紧挨着 `?123`。理由：安卓的模式切换键都在键盘左下角，肌肉记忆一致。
- 键面文案随当前模式变化：26 键模式显示「**九键**」，九键模式显示「**26键**」，符号页显示进入符号页前的那个布局名。
- 宽度预算：现有 `?123` 是 `layoutWeight(1.3)`；新增键给 `layoutWeight(1.2)`，`?123` 降为 `1.2`，空格保持 `4`（≈底栏 40%），`中/英` 1、`⌫` 1.2、`⏎` 1.3 不变。**竖屏不能出现「空格被挤到 1/3 以下」**。

### 3.2 状态机（在现有 `switchPanelMode` 上加，不新建第二套）

- `panelMode` 仍是三态：`'qwerty' | 'symbol' | 't9'`。
- **新布局键的行为**：
  - 在 `qwerty` → `switchPanelMode('t9')`
  - 在 `t9` → `switchPanelMode('qwerty')`
  - 在 `symbol` → 先回到**进入符号页之前的布局**（`qwerty` 或 `t9`，用一个 `prevPanelMode` 字段记住）
- **`?123` 键的行为**（改掉现在「非 qwerty 一律回 qwerty」）：
  - 在 `qwerty` / `t9` → 进符号页（并记 `prevPanelMode = 当前模式`）
  - 在 `symbol` → 回 `prevPanelMode`（**九键用户从符号页回来应该还是九键**，不是被踢回 26 键）
- **引擎联动全部沿用 H-047 已有代码**：`switchPanelMode()` 里 `selectSchema('sansheng_t9')` ↔ `selectSchema('wubi_pinyin')` + `syncEngineOptions()` 回填中英/简繁键面。**不要另写一套切换逻辑**，否则会出现「键面是九格、引擎还在 26 键方案」这类漂移。
- **切换前清挂起编码**：切布局时先 `keyboardController.clear()`（和 H-045 中英切换同一处理），否则九格里的 `644` 会被切到 26 键方案里继续跑。

### 3.3 符号页的「九宫格」标签：删掉

`SYMBOL_TABS` 去掉第 6 项「九宫格」，变成 5 类（常用/数学/货币/箭头/英文）。理由：

- 符号页是**符号分类**，塞一个键盘布局进去是语义错位；
- 主人已经点名「打开后还得选九宫格」这个路径不合格，留着等于留一条歧路；
- 标签数从 6 变 5，符号页排版不需要重做（`layoutWeight(1)` 均分）。

### 3.4 本次**不做**（避免范围蔓延，写进备注）

- 九格数字键**长按直出数字/符号**（安卓标准做法）：与 H-047「九格数字进编码」是两条路径，长按直出需要面板加长按手势 + 桥侧区分短按/长按，**单独立单**，本次不做。
- 九格「1」键的特殊语义、0 键长按空格：留 M5。
- 键盘布局选择的持久化（记住用户上次用九格还是 26 键）：**建议做**，但要放在设置项里，不是底栏；可下一轮。

## 5. 同批交付的第二个改动（同一文件，一起改，省一轮）

**H-055 · 候选页大小按「全量候选」算，别按「当前页切片」算**（`KeyboardIndex.ets:recomputePageSize()`）

- 现状：页大小是拿 `this.candidates`（**当前页切片**）估宽算出来的。Rime 的菜单页实测 `page_size=50`，每次输入的候选条数在 3/4/7/8/10/13/15/50 之间跳，于是：
  - 第 1 页 8 条 → 算出 8 → `setPageSize(8)`；
  - 翻页后当页只剩 3 条 → 又按 3 条重算 → `setPageSize(3)` → **页大小被当前页条数绑架（棘轮）**，越翻越小/越跳。
- **修法**：改用**全量候选** `state.allCandidates`（引擎已提供，v0.2.0 接口）来估宽；**并且只在编码串（composition）变化时重算** `setPageSize`，翻页不重算（否则会打断引擎分页状态）。
- 引擎侧管道已就绪（Qoder 已落 `inputmethod/KeyboardController.ets`）：`KeyboardState.allCandidates`（本页在 Rime 菜单页内的完整列表）+ `KeyboardState.baseIndex`（`allCandidates[0]` 的全局绝对下标）+ `chooseCandidateAbs(absIndex)`。
- **验收**：竖屏打 `nihao`，一条候选都不许少；连续翻 3 页，页大小**不发生变化**（日志里 `setPageSize` 不重复出现）。
