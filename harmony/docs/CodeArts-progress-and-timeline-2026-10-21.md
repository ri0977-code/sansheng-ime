## 一、kanonIME 参考覆盖度分析

kanonIME 是日语输入法（MIT 许可证，派生自 OpenHarmony KikaInputMethod 官方示例 Apache-2.0），我们抄的是它的**候选栏 UI 布局**。三生输入法的目标远不止候选栏，覆盖度分块如下：

### 逐项对照

| 三生目标 | kanonIME 覆盖？ | 说明 |
|---|---|---|
| 候选栏双行布局 | ❌ 已作废 | 主人 19:12 否决双行（D-003），改回单行（D-004） |
| ▼ 展开网格 | ✅ 直接抄 | `Scroll + Flex(wrap)` 覆盖键盘区，点词上屏自动收起 |
| 行高自适应 + 降级 | ✅ 直接抄 | 剩余 <160vp 自动退回单行，治 H-037 横屏首帧裁切 |
| 选中项自动跟随 | ✅ 直接抄 | `scrollToIndex(i, true, CENTER)` |
| 五笔+拼音混输 | ❌ | kanonIME 是日语，没有中文输入逻辑 |
| 三向反查 comment | ❌ | 日语没有反查概念；反查行是我们抄 fcitx5-android 设计补的 |
| 简繁转换 (OpenCC) | ❌ | 日语不需要 |
| 九宫格 T9 | ❌ | 日语不用九宫格 |
| Lua 滤镜 (13 个齿轮) | ❌ | kanonIME 没有 Lua |
| 词库闭包 | ❌ | kanonIME 没有 |
| 弹性候选栏 (按宽度算条数) | ❌ | kanonIME 是固定布局，不是弹性的 |
| 左右滑翻页 | ❌ | kanonIME 的翻页是按钮，不是手势 |
| 中英/简繁合键 | ❌ | 日语不需要 |
| 26键/符号页/数字行 | ❌ | kanonIME 是日语布局 |
| Rime 引擎集成 | ❌ | kanonIME 用自己的日语引擎 |
| 预编辑处理 | ❌ | 日语假名转换 ≠ 中文编码 |

### 按工作量估算

| 大块 | 占比 | kanonIME 覆盖度 | 备注 |
|---|---|---|---|
| 引擎侧（Rime 桥、数据、Lua、词库、OpenCC） | ~40% | 0% | Qoder 负责，与 kanonIME 无关 |
| 候选栏 UI（单行+反查行+展开网格） | ~15% | ~30% | 双行已作废（D-003），单行+预编辑独占上一行按 fcitx5 层结构重写（D-004），kanonIME 可复用的只剩 ▼ 展开网格和选中跟随 |
| 键盘壳（IME 生命周期、面板管理、横竖屏） | ~15% | ~10% | 面板生命周期可参考，其余自己写 |
| 键盘布局（26键、九宫格、符号页、数字行） | ~15% | 0% | 日语布局完全不同 |
| 交互逻辑（翻页、中英切换、简繁、Shift） | ~15% | 0% | 全部自己写 |

### 结论

**kanonIME 大约覆盖整个项目目标的 2 成左右（~15-20%）。** 但它覆盖的这 2 成正好是我们之前反复改了 5 轮（H-035/H-042/M-030）都没改好的部分——候选栏密度、横屏首帧裁切、双行布局、展开网格。它的价值不在于覆盖比例高，而在于解决了最难的 UI 瓶颈。

### fcitx5-harmony（已排除）

- 仓库：`github.com/fcitx-contrib/fcitx5-harmony`，GPL-3.0
- 关键发现：键盘 UI 用 WebView + HTML/CSS/JS 渲染，非纯 ArkTS
- 结论：GPL-3.0 + WebView 方案，只借设计不搬代码，不作为主参考
- 详细研究文档：`docs/evidence/2026-10-21/fcitx5-harmony-research.md`

### 不确定因素

1. **H-048 真机验证**——面板高度从 274vp→236vp（竖屏 44+48×4）、180vp→180vp（横屏 44+34×4），单行版变更较小，但仍需验横屏首帧不裁切。
2. **M5 皮肤范围**——如果主人觉得当前文字键够用、不需要键帽图标和触感，M5 可以大幅缩减甚至跳过。
3. **APP 备案**——工信部备案审核周期通常 1-20 个工作日，这是最大的不确定因素。但备案期间可以继续用调试签名自测。
4. **软著/电子版权证书**——AGC 上架必填项。**建议双轨**（D-006）：先办电子版权（约 2 周/几百元）跑通上架流程，同时免费提交官方软著登记（0 元/2~3 月）作长期权属凭证。华为侧两者等效。官方软著法律强度最硬（维权/跨平台/转让都用），电子版权弱一档但过平台审核够用。**这才是上架的关键路径，不是代码**。
5. **H-007 许可不一致**——根 `LICENSE` 是 MIT，`fanxing_rime_har` 包声明 Apache-2.0，上架前必须定案。
6. **正式开发者证书/账号资质**——目前全程调试签名（2027-10-19 到期），没有发布证书、发布 Profile、软著/电子版权、APP 备案号、隐私政策链接。详见 `docs/RELEASE-READINESS.md`。
7. **H-040 横屏可用宽度只有约 610vp**——直接决定一页几条候选，和弹性/单行绑死。
8. **九宫格要不要按出英文单词**——无需求单，等 M5 一起拍。
9. **性能与内存无目标值**——面板首帧 / 常驻内存 / 词库重编基线 4,120 ms，均无量化目标。
10. **`DATA_VERSION` 变更后老数据迁移无方案**——目前靠 uninstall+重装，正式用户升级时不能这样。
