## 3. 根因（读代码量出来的，不是猜）

`KeyboardIndex.ets` 的 `FuncIcon(action)` 里，这枚图标**从来没有「选中态」底色**——常态是透明的
（H-179 定稿：安卓实物那排图标没有常态底色，按下才浮一层浅灰）。所以那块灰**只可能是按压色没退掉**。

按压色挂在框架的按压样式态（`stateStyles({ pressed: … })`）上，而 ⇆ 的 `onClick` 会改 `funcSubPanel`，
`build()` 里键区是 `if (expanded) … else if (funcSubPanel==='textedit') TextEditGridPanel() else if …
QwertyPanel()` 这种**整块换 builder** 的分支 ⇒ 按下期间触发重渲染，抬手后那个 pressed 态没被复位。
同一条路上「‹」「▼」是收起整条工具栏（图标直接没了），所以看不出问题——这也是上一轮量 P4 没量到病的原因。

## 4. 两轮修法（`entry/src/main/ets/pages/KeyboardIndex.ets`，只动 `FuncIcon` 一枚）

**r1（01:0x，装机 01:11，unsigned 28,377,555 / signed 28,503,822，updateTime=1793121003924）**
——不再让框架握这个态，改走本文件键面 M-049 已经在用、真机验过会复位的通路：
新增 `@State pressedFuncIcon: string = ''`；底色 `pressedFuncIcon === action ? FUNC_ICON_PRESSED : Color.Transparent`；
`.onTouch` Down 上色 / Up·Cancel 清色；`.onClick` 动作后兜底再清一次；`#DCE2EC` 提成常量 `FUNC_ICON_PRESSED`。
「···」菜单那排磁贴（`FuncTile`）仍走原样式态，本轮不扩面（见 §7）。

**⇒ r1 修坏了**：主人 01:1x 原话「**现在连选中都没有颜色了！**」
我确实把「不复位的灰」去掉了，但顺带把「面板开着时这枚图标应该看得出是它开的」一起抹了 ——
H-179 那句「安卓那排图标没有常态底色」我照搬得太硬：安卓有没有选中态我根本没量过，
而他这句才是最终事实。

**r2（01:2x，装机 01:20，unsigned 28,378,309 / signed 28,503,438，updateTime=1793121616121）**
——底色改成**三层**，按下态优先、其次选中态、都没有才透明：

```ets
.backgroundColor(this.pressedFuncIcon === action ? FUNC_ICON_PRESSED
  : (this.funcIconOn(action) ? BG_ACTIVE : Color.Transparent))
```

选中态由面板状态算出来，不是另一个要人记得清的开关（与 H-234「单一出口」同一个思路）：

```ets
private funcIconOn(action: string): boolean {
  if (action === 'cursor') { return this.funcSubPanel === 'textedit'; }
  if (action === 'clipboard') { return this.funcSubPanel === 'clipboard'; }
  return false;
}
```

⇒ 面板开着 ⇆ 挂 `#B8C6E8`（和键面功能键同一个选中色），折叠 ⇒ 回栏底；「···」里的剪贴板格子同理。
