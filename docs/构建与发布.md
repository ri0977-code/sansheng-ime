# 构建与发布（面向想自己打包的人）

三生输入法 = 小狼毫 Rime 引擎 + 一层配置/Lua 滤镜。发出去的东西有两块：**setup.exe**（给普通用户双击）和 **配置源码**（给想自己改的人）。

## 一、目录分工

| 目录 | 作用 | 进不进 git |
|------|------|-----------|
| `rime-config/` | 本机生效配置的镜像（override + 两张英文权重表 + 抬权明细），改动可追溯 | ✅ 进 |
| `packaging/installer-src/` | 安装器源码：`install.nsi` + 四个辅助脚本 | ✅ 进 |
| `packaging/stage/` | 打包中间树（引擎 + 全量配置，77 MB） | ❌ 不进（太大） |
| `packaging/release/` | 对外发布树 = stage 清洗后的产物 + 铺入的安装器源码 | ❌ 不进 |
| `packaging/dist/` | 成品 `三生输入法-vX.Y-setup.exe` | ❌ 不进，走 GitHub Release 附件 |

## 二、一条命令重建安装包

```bat
python packaging\prepare_release.py
```

它按顺序做：

1. 从 `packaging/stage/` 清洗出 `packaging/release/`：剔除 `user.txt`（自调频打字记录）、`user.yaml`、`installation.yaml`、`Custom_phrase.txt`（个人短语）、`lua/*personal*.txt`、`runLog.txt`、`*.bak/.orig/.sw-/.userdb`、`.bak` 目录、`sync/`、小狼毫自带 `uninstall.exe` 与 `rime-install*.bat`；
2. 给 `lua/phraseExt personal.txt`、`lua/phraseComment personal.txt` 生成**同名空模板**（上游 lua 会读这两个文件，缺文件会报错，所以「文件在、内容为空」最稳）；
3. 生成中性 `Custom_phrase.txt` 模板；
4. **硬校验**：两张英文权重表的 md5 必须等于本机 `D:\Program Files\Rime` 的当前值，不等直接判失败；
5. 个人数据扫描（发布前铁律，命中即失败）；
6. 把 `packaging/installer-src/` 铺进 release（`.nsi`/`.ps1` 统一重写成 **UTF-8 with BOM**——NSIS 和 PowerShell 5.1 没有 BOM 会把中文按 ANSI 解析）；
7. 调 `makensis` 编译出 `三生输入法-vX.Y-setup.exe`，并复制一份到 `packaging/dist/`。

结尾必须打印 `全部校验通过 ✓`。任何 `!! 问题:` 都不要发布。

只想校验不写文件：`python packaging\prepare_release.py --check`。

## 三、编译器

NSIS 3（本机在 `D:\Program Files (x86)\NSIS\makensis.exe`，`prepare_release.py` 会自动找）。
手动编译：

```bat
cd packaging\release
"D:\Program Files (x86)\NSIS\makensis.exe" -V1 install.nsi
```

## 四、安装器干了什么（`installer-src/install.nsi`）

装：引擎 → `%ProgramFiles%\Rime\weasel-0.17.4`；配置 → **自动检测**的 Rime 用户目录（`HKCU\Software\Rime\Weasel\RimeUserDir`，没有才用 `%APPDATA%\Rime`，绝不改写别人已有目录）；铺配置前先把旧配置备份成 `sansheng-backup-时间戳`；`weasel.dll`/`weaselx64.dll` → System32 / SysWOW64；导入 4 个 `.reg` 后立刻用 `WriteRegStr` 把 `IconFile` 改成真实安装路径（NSIS 不会展开 `.reg` 文件里的 `$INSTDIR`，所以这一步必须在运行时做）；`WeaselDeployer /deploy` 编译词库；`enable-tip.ps1` 把输入法加进当前用户键盘列表（读-改-写、幂等，不会把别的输入法弄丢，也不用注销重启）；写控制面板卸载入口 + 开始菜单。

卸：`WriteUninstaller` 生成的卸载段 + 独立脚本 `卸载三生输入法.cmd`（默认干跑，加 `-Apply` 才动手，还会自己申请管理员）。两者都**只删三生自己放进去的东西**；当安装目录 == Rime 用户目录时目录本身保留，绝不动词库与打字记录。

## 五、发布检查清单

- [ ] `prepare_release.py` 打印 `全部校验通过 ✓`
- [ ] `makensis` 零警告通过，exe 体积正常（约 28—29 MB）
- [ ] 在**一台干净机器/虚拟机**上完整走一遍：装 → `Win+空格` 切到三生 → 打五笔/拼音/英文/简繁 → 卸载 → 确认词库还在（这一步本机生产环境不能替代）
- [ ] 杀毒软件误报预判：NSIS 安装包 + 写 System32 的行为容易被启发式拦截，Release 页面要写清「数字签名暂缺，属正常」
- [ ] README 的 `安装` / `版本沿革` 与 exe 版本号一致
- [ ] `.git/config` 里 remote URL 不要带明文 token（改用 `gh auth` 或 SSH；已经泄露过的 token 去 GitHub 后台 revoke 重建）

## 六、词库从哪来

`wubi86` / `easy_en` / `dyyWubi` / `latex` 等来自上游开源词库（见 `LICENSE` 与引擎目录 `LICENSE.txt`），三生自己动的是两张中英映射表的**权重字段**（`zh2en_pinyin_wp` / `zh2en_wubi_wp`，只改权重、不增删词条，明细见 `rime-config/dicts/`）。遵循 Rime 铁律：**绝不手动往词典里塞词**，自造词一律交给自动组词与 `Custom_phrase`。

## 七、发布到 GitHub（v1.9 已走完，记下来给下一版照着做）

线上地址：仓库 `https://github.com/ri0977-code/sansheng-ime`（原名 `wubi-citong`，2026-10-18 在 Settings → Repository name 改的名，旧地址自动重定向）、Release `v1.9`、安装包附件 `sansheng-ime-v1.9-setup.exe`。

### 1. 内容推送：走 git，不走网页逐文件上传

本机 `git push` 之前连不上 `github.com:443`，原因是命令行没走浏览器的代理；加上 `-c http.proxy=http://127.0.0.1:10810`（v2ray/xray 的 HTTP 端口，按自己机器改）就通了。凭据由 Git Credential Manager 提供，`.git/config` 的 remote URL 里**不要再写 token**。

远端 `wubi-citong` 与本地是**两条独立历史**（本地不是从它 clone 的），直接 push 会被拒。别用 `--force`（会把远端 `rime/`、`使用说明/`、CI 全抹掉）。正确做法是合流：

```bat
git fetch origin master
git merge origin/master --allow-unrelated-histories
```

只有三个文件冲突，v1.9 的处理方式：`.gitignore` 两边规则取并集；`README.md`、`install.bat` 保留本地版本，远端原文**原样归档**到 `使用说明/旧版首页-五笔词通-v1.0.md`、`使用说明/旧版安装脚本-五笔词通-v1.0.txt`（只备查，不双击）。合并后 `master` 同时含有远端的 `rime/`（上游完整配置树 + lua）、`使用说明/`、`.github/workflows/release.yml`、`.gitattributes` 和本地的 v1.9 增量。

### 2. 推送前必做：全文扫描

`git ls-files` 全量扫 `ghp_` / `github_pat_` / `token=` / `password=`，以及 `user.txt`、`user.yaml`、`installation.yaml`、`Custom_phrase.txt`、`*personal*.txt`、`*.log`、`*.userdb`。命中一个都不推。（v1.9 扫过：164 个文件 0 命中。）

### 3. 建 Release 与传安装包

- 网页 `Releases → Draft a new release`：Tag 填 `v1.9`、Target `master`，正文写清下载链接、安装 3 步、卸载位置、sha256、以及「未签名，SmartScreen 选仍要运行」。
- **附件文件名用 ASCII**（`sansheng-ime-v1.9-setup.exe`）：中文名那次上传直接报 "Upload failed"，换英文名后成功。
- 28.7 MB 的 exe 在这台机器上**失败过两次**才成功。判断标准不是「选了文件」，而是 Assets 那一行出现 **`(28.68 MB)`** 且没有 "Upload failed"，再点 **Update release**。行显示失败就先 Remove、重新拖、多等一会儿。
- 传完用 API 复核（无需凭据）：`https://api.github.com/repos/<用户>/<仓库>/releases/<id>` 看 `assets[0].state == uploaded`、`size` 与本地字节数一致、`digest` 等于本地 `sha256`；再 `curl -sIL <browser_download_url>` 应拿到 302→200 且 `Content-Length` 与本地一致。

### 4. CI 的改动（v1.9）

原 `.github/workflows/release.yml` 会在打 `v*` 标签时自动把 `install.bat + rime/ + 使用说明/` 打成 `wubi-citong-vX.Y.zip` 挂上 Release。合流后根目录 `install.bat` 换成了 v1.7 的 codeLookup 补丁脚本，再照旧打出来的 zip「脚本」和「配置树」对不上，所以这条流水线改成：只跑两项静态校验（bat 首行与编码、`校验安装包.py` 查 `rime/` 依赖完整性）+ 自动建 Release，**附件由发布人手动上传 setup.exe**（CI 是 ubuntu runner，编不了 NSIS）。
